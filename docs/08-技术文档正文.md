## 1 项目概述

### 1.1 背景与痛点

高校软件工程、Python 程序设计、数据库与 Web 开发等实训课程中，学生遇到报错或概念卡点时，普遍的做法是把题目或整段代码交给通用 AI，复制生成的实现提交。由此产生三个问题：

1. **学习过程被替代**：学生得到的是答案，不是排查思路，下次遇到同类问题仍然不会处理。
2. **幻觉无法核对**：通用模型会生成看似合理但不存在的函数名、参数与「参考资料」，学生没有能力判别。
3. **脱离课程实际**：模型给的解法常超出本课程已讲授的知识范围，与教师指定的教材、实验手册不一致。

现有教学工具要么只做资料检索（没有引导），要么直接接入通用聊天模型（没有约束），缺少一个「既用 AI、又不让 AI 代写作业」的中间形态。

### 1.2 作品定位

知实 AI 是一个**面向高校软件工程实训的 RAG 智能答疑知识库**：只依据教师上传的课程资料作答，每条结论附可点开核对的引用；资料里没有的内容明确说明「资料不足」，不编造引用；默认不输出可直接提交的完整实现，而是以 L1→L4 四级提示引导学生自己改出来。

产品的四条底线：

| 底线 | 具体含义 | 实现位置 |
|---|---|---|
| 有据可查 | 每条结论附文档名、页码 / 段落，可展开原文片段与相关度 | `teaching/engine.py: build_citations` |
| 无据则明说 | 命中分数低于阈值或资料不覆盖时，明确告知并停止生成 | `engine.py` 的 `min_evidence_score` 分支 |
| 引导优先 | 默认不给完整实现，分级解锁，且不能跳级 | `engine.py: respond` 的层级钳制 |
| 演示模式诚实 | 未配模型时检索真实执行、回答由模板生成并显著标注 | `core/config.py: demo_mode`、`llm/client.py` |

### 1.3 核心能力一览

- **课程知识库**：PDF / DOCX / TXT / Markdown 上传、解析、分块、Chroma 持久化索引、内容 sha256 去重、删除同步清向量、重建索引、分块预览。
- **分层教学引擎**：六类问题自动分类（可手动覆盖）、两种教学模式、四级提示、跳级拦截、答案泄露护栏、学生提交反馈。
- **截图报错分析**：本地 OCR / 视觉模型双通道、识别文字可编辑后重跑、异常字段解析、复用同一套检索与教学链路。
- **演示模式与一键复现**：无 Key、断网也能完整走通主流程；干净机器 5 步、10 分钟内可复现。

### 1.4 与通用 AI 问答的差异

| 维度 | 通用 AI 问答 | 知实 AI |
|---|---|---|
| 知识来源 | 模型参数记忆，来源不可核对 | 教师上传的课程资料，引用可展开 |
| 无依据时 | 倾向于生成「合理」的答案 | 明确「资料不足」，不伪造引用 |
| 输出形态 | 直接给完整实现 | L1 概念 → L2 思路 → L3 诊断片段 → L4 迁移例题 |
| 学生参与 | 一次提问即结束 | 引导模式需先提交自己的尝试才解锁 L3 |
| 断网 / 无 Key | 不可用 | 检索与引用真实执行，模板回答并标注 |
| 代码安全 | 可能执行或建议执行未知代码 | 全链路不执行用户代码，无 `exec` / `eval` / `subprocess` |

## 2 需求分析

### 2.1 用户角色与典型场景

| 角色 | 诉求 | 对应功能 |
|---|---|---|
| 学生（主要用户） | 卡住时得到**能自己走下去**的提示，且知道依据在哪 | 分层教学页、报错分析页、引用卡片 |
| 教师 / 助教 | 让答疑口径统一到本课程资料，可自行补充资料 | 知识库上传、删除、重建、分块预览 |
| 评委 / 复现者 | 不配密钥、10 分钟内看到完整主流程 | 演示模式、一键复现、自检脚本 |

典型场景：学生在实训中遇到 `TypeError: can only concatenate str (not "int") to str`，把报错截图或文本提交 → 系统 OCR / 解析 → 检索课程资料 → 分类为「编程报错」→ 返回 L1（解释异常类型 + 引用原文，不给代码）→ 学生写思路提交 → 解锁 L2 排查顺序 → 再解锁 L3（≤6 行诊断片段）→ L4 换条件的相似例题。

### 2.2 功能性需求

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-1 | 支持四类课程资料上传、解析并保留页码 / 标题 | 上传 DOCX 后在分块预览中看到页码 |
| FR-2 | 同一内容重复上传不产生重复索引 | sha256 去重测试 |
| FR-3 | 删除文档时同步清除向量 | 删除后检索不再命中 |
| FR-4 | 检索结果必须携带文档名、位置与相关度 | 引用卡片可展开 |
| FR-5 | 资料不覆盖时明确拒答，不伪造引用 | 提问「量子计算机会取代经典计算机吗？」 |
| FR-6 | 分级提示不能跳级，引导模式下未提交尝试不得进入 L3 | 传 `target_level=4` 时服务端压回 2 |
| FR-7 | 不输出可直接抄交的完整实现 | 护栏测试：代码块截断 / 骨架替换 |
| FR-8 | 报错截图识别结果可人工修正并重跑 | 「用修正后的内容重新分析」 |
| FR-9 | 无大模型密钥时主流程完整可用且标注演示模式 | `DEMO_MODE=auto` 无 Key 启动 |

### 2.3 非功能性需求

- **离线可用**：检索与 OCR 的本地通道不依赖外网、GPU 或 Embedding API。
- **可复现**：干净机器 5 步、≤10 分钟；`storage/` 不入库，但 `seed_demo.py` 可一键导入演示资料。
- **安全**：密钥只存后端环境变量；前端拿不到；健康检查只回布尔值；不执行用户代码；前端富文本经 DOMPurify 处理。
- **诚实可解释**：任何由模板或模型生成的内容都有明确标记；OCR 行号始终标注「识别，可能不准」；L4 例题标注「AI 生成示例 · 非教材原文」。
- **可维护**：后端按领域分模块，接口契约用 Pydantic 模型约束，OpenAPI 文档自动生成。

### 2.4 明确的边界（不做的事）

本项目**不做**：登录与多租户、教师端学情看板、自动评分、执行或运行学生代码、直接给出完整作业实现、联网抓取资料。这些边界既是教学伦理选择，也让系统保持轻量、可离线复现。答辩时可说明：官方要求「后端仅作 AI 能力接入层」，因此未引入账户体系等重型业务模块。

### 3.3 核心数据流

**问答链路**：前端提交问题 → `/api/teaching/hint` 若未带检索结果则由 `CompositeRetriever` 补齐 → `classify` 六类分类 → `respond` 计算目标层级并钳制 → `build_citations` 依据命中集合生成引用 → 组装分层内容块 → 有模型则润色 L1–L3 → `guard_blocks` 输出侧护栏 → 返回 `TeachingResponse`（含 `llm_status`）。

**报错分析链路**：上传截图 → 图片校验与缩放 → OCR 通道识别（本地 rapidocr / 视觉模型 / auto）→ 用户可修正识别文字 → `parser` 解析异常类型、文件路径、行号 → 复用检索与教学引擎 → 返回可能原因、排查步骤、引用卡片。行号始终标注「识别，可能不准」。

**资料入库链路**：上传 → 格式与大小校验 → 解析器提取带页码 / 标题的 `Block` → `chunker` 按段落聚合 → `embeddings` 生成哈希向量 → `index` 写入 Chroma → `store` 更新登记表（状态、片段数、sha256、失败原因）。

### 3.5 数据模型要点

`RetrievedChunk` 统一了两套检索的返回结构（文本、文档名、页码 / 段落、相关度、块 ID），使教学引擎与报错分析无需感知检索来源；缺失元数据保持 `None`，界面如实显示「未标注」而不是编造。引用 `Citation` 由 `build_citations` 依据**本次命中集合**生成，因此引用编号不可能指向未检索到的文档。

## 4 AI 技术方案

> 本章对应官方「AI 技术说明须重点阐述选型理由、集成方式、优化策略」的要求，是全文最高权重章节。

### 4.1 技术选型与理由

| 技术点 | 选择 | 选型理由 | 放弃的方案及原因 |
|---|---|---|---|
| RAG 框架 | **自建链路**（约 200 行核心逻辑） | 需要精确控制「引用必须来自本次命中集合」「检索结果驱动分层策略」，框架封装会掩盖这些约束；且便于教学展示与单元测试 | LangChain 等：抽象层厚，定制护栏与引用绑定反而更绕 |
| 向量化 | **离线哈希向量** | 现场可能没有 Embedding API、没有 GPU；交付首要目标是「稳定可演示」。字符 2/3-gram + 英文单词经 crc32 散列到 512 维、L2 归一化，属于**词面相似度**，配合字面覆盖率足够覆盖课程资料问答 | 语义 Embedding：需外网 / API / 本地模型，离线演示有风险 |
| 向量库 | **Chroma 持久化** | 嵌入式、无需独立服务，`storage/chroma` 可直接落盘；集合 `library_chunks_v1`，`hnsw:space=cosine` | Qdrant：需额外服务进程，违背「10 分钟极速复现」 |
| 排序 | **0.75 余弦 + 0.25 字面覆盖率** | 纯词面哈希对中文近义表达不敏感，加字面覆盖率可稳定命中关键词型报错；两路分数可直接解释 | 纯向量排序：短查询与专业术语容易漂移 |
| 大模型接入 | **OpenAI 兼容 `/chat/completions`** | 只用 `messages / temperature / max_tokens` 最小公共子集，换供应商只改 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 三个环境变量；不依赖 function calling | 厂商私有 SDK：锁定供应商、增加依赖 |
| 前端 | Vue 3 + Vite + TypeScript | 类型安全、构建快、组件化适合四级阶梯与引用卡片 | — |

> 诚实说明：哈希向量是**词面相似度，不是语义向量**，不具备同义 / 泛化能力。这一点在答辩中应主动说明，并把它定位为「离线可复现优先」的工程取舍，而不是宣称达到语义检索效果。

### 4.2 RAG 链路实现

**分块**：`chunker.py` 按段落聚合，目标 500 字、重叠 80 字、上限 800 字，句子边界与代码块不被硬切，保留 `page` / `heading` / `ordinal`，因此引用能定位到真实页码与标题。

**向量化**：`embeddings.py` 的 `embed_text` 提取英文单词与中文连续串的 2/3-gram，用 `zlib.crc32` 散列到 512 维桶并累加，最后 L2 归一化；`lexical_coverage` 计算查询特征在文本中的覆盖率。全过程纯 CPU、零网络请求。

**索引**：`index.py` 使用 Chroma 持久化集合，`upsert` 写入块 ID、向量、文档元数据；删除按 `doc_id` 精确清除；`search` 取回 `distances` 换算余弦后按 `0.75 × cosine + 0.25 × lexical` 打分，低于 `min_score` 丢弃。

**组合检索与回落**：`CompositeRetriever.search` 先查知识库，命中不足 `top_k` 时用内置示例资料的 `KeywordRetriever`（IDF 加权词面匹配）补足，再按分数降序、以 `(doc_name, text[:60])` 去重后截断。这一设计使「知识库为空」时系统仍可用，同时保证两套检索返回同一数据结构。

**引用绑定**：`build_citations` 只从本次 `retrieval` 列表生成引用，配合 `min_evidence_score` 阈值；片段未真正覆盖问题时会补一段明确标注「通用 Python 知识（非课程资料）」的诊断，既不伪造引用，也不简单拒答。

### 4.3 大模型集成方式

`llm/client.py` 的 `LLMClient` 通过 `httpx` 调用 `{LLM_BASE_URL}/chat/completions`，请求体包含 `model`、`messages`、`temperature`（默认 0.3）、`max_tokens`（默认 1200）、`stream: False`，带超时与重试；`available` 由 `llm_api_key / llm_base_url / llm_model` 三者是否齐备决定。

**集成点**：`teaching/engine.py` 在 L1–L3 生成后，若模型可用则调用 `compose_hint`，把「问题、分类、层级、可信检索片段、当前讲解块」一起送入模型做**受约束的润色**，而不是让模型自由回答；模型输出要重新经过引用校验与 `guard_blocks` 才能返回。响应中的 `llm_status` 取值为 `template`（未配模型）、`model`（模型成功）、`fallback`（模型失败回退模板），前端据此显示状态。

**降级设计**：模型超时、返回异常、格式不合法时自动回退到模板讲解，检索与引用完全不受影响；`DEMO_MODE=on` 可强制演示模式，`auto` 则在无 Key 时自动进入。现场网络故障可一键回退，这是答辩中值得强调的稳定性设计。

**当前明确未做的**：`stream: False`，全项目无 SSE 流式输出；无 Agent / 工具调用 / Function Calling；无独立 RAG 对话页。这些属于后续规划，不在当前实现中，不得写入已完成功能。

### 4.4 提示词工程与分层教学策略

系统把「教学策略」编码成结构化的内容块，而不是一句自由 Prompt：

- **六类问题**：概念理解、编程报错、实验步骤、数据库与 SQL、Web 开发、作业思路；分类结果带置信度且允许用户手动覆盖。
- **两种模式**：学习模式（study）与引导模式（guided）。引导模式下，进入 L3 前必须先提交自己的思路或代码片段，否则服务端把请求压回 L2 并说明原因（`guided_requires_attempt`）。
- **四级提示**：L1 知识点提示（解释概念 + 引用原文，不给代码与步骤）→ L2 解题思路（4–6 步检查顺序）→ L3 局部示例（≤6 行诊断片段）→ L4 相似例题（同知识点、换条件，标注「AI 生成示例 · 非教材原文」）。
- **跳级拦截**：服务端按 `current_level + 1` 钳制 `target_level`，`clamped` 与 `clamp_reason` 随响应返回，前端无法绕过。

关键设计是**检索结果直接驱动分层策略**：L1 只引用原文，L2 组织方法，L3 给诊断片段，L4 做迁移，检索命中集合同时决定引用编号的合法范围。这使「AI 功能」不是附加在页面上的聊天框，而是贯穿答疑主流程的核心逻辑。

### 4.5 AI 安全与可控

| 风险 | 措施 | 位置 |
|---|---|---|
| 模型编造引用 | 引用只能来自本次命中集合；低于阈值走拒答 | `build_citations`、`min_evidence_score` |
| 直接给可抄的完整答案 | 代码块 >6 行截断、完整函数体替换为骨架、命中「完整代码 / 直接复制」话术自动收敛 | `guards.py`、`engine.py` |
| 学生提交恶意代码 | 只做文本分析，全模块无 `exec` / `eval` / `subprocess` | 全后端 |
| 密钥泄露 | 只放后端 `.env` 或系统环境变量，前端不接触；健康检查只回 `llm_configured` 布尔值；`.gitignore` 排除 `.env` | `core/config.py`、`.gitignore` |
| 前端 XSS | 富文本渲染经 DOMPurify 清洗 | 前端 |
| OCR 猜测被当成事实 | 识别文字可编辑、行号标注「识别，可能不准」 | `errors/`、`ErrorView.vue` |
| 模板 / 生成内容冒充 | L4 标注 AI 生成；通用知识标注「非课程资料」；演示模式顶部横幅 | `templates.py`、前端 |

### 4.6 优化策略与权衡

1. **混合打分**：向量余弦与字面覆盖率互补，缓解纯哈希向量对中文近义表达的不足，且分数可解释、便于调参。
2. **回落与去重**：知识库命中不足才启用示例资料词面检索；`(doc_name, text[:60])` 去重避免同一片段重复占满 `top_k`。
3. **缓存**：`get_retriever()` 用 `lru_cache(maxsize=1)` 复用检索器；Chroma 客户端用锁 + 字典缓存，避免重复创建连接。
4. **失败隔离**：知识库检索抛异常时返回空列表而非 500，再由回落通道兜底；模型失败回退模板，主流程不中断。
5. **可复现优先**：`storage/` 不入库，但 `seed_demo.py` 直接写本地索引、无需先启动服务；`check_demo.py` 不依赖 HTTP 服务即可自检。
6. **取舍说明**：为保证离线与可复现，牺牲了语义召回率；前端主 chunk 1.11 MB（gzip 约 369 KB）尚未做代码分割，属于已知性能债，已列入后续规划。

### 4.7 演示模式：把「诚实」做成功能

未配置 `LLM_API_KEY` 时，`DEMO_MODE=auto` 自动进入演示模式：检索、引用、分类、层级、护栏**全部真实执行**，只有讲解文字由模板生成，界面顶部明确标注「演示模式」，响应 `llm_status=template`。断网、无 Key 也能完整走通主流程，评委 clone 下来无需任何环境变量即可打开页面。

这一设计同时满足两点：一是「10 分钟极速复现」，二是避免把模板输出伪装成模型输出。配置 Key 后重启后端，`/api/health` 的 `demo_mode` 变为 `false`、`llm_configured` 变为 `true`，即可展示真实生成效果，且 Key 不进入仓库。

> 参数口径说明：`/api/health` 回显的 `embed_dim: 1024` 是 `config.py` 中为将来接入语义 Embedding 预留的配置默认值；当前离线哈希向量由 `embeddings.py` 固定为 **512 维**（`EMBED_VERSION = hash-char-ngram-v1`）。健康检查回显的是配置，不是实际向量维度，两者不冲突。

## 5 核心功能实现

### 5.1 课程知识库（`app/library/`）

支持 PDF（PyMuPDF，保留页码）、DOCX（python-docx，保留标题层级）、TXT、Markdown；单文件上限可配（默认 20 MB）。解析失败如实上报具体原因（扫描版 PDF、空文件、编码异常），不做静默跳过。按内容 sha256 去重，删除文档时调用 `collection.delete(where={"doc_id": ...})` 同步清向量，避免「删了还能检索到」。提供重建索引与分块预览，教师可核对实际切出来的片段与页码。首页与 `/api/health` 的文档 / 片段数来自真实登记表，未导入时如实返回 `not_initialized`。

> 配图：`docs/assets/library.png`（知识库列表与状态）。

### 5.2 分层教学（`app/teaching/` + `TeachingView.vue`）

页面提供「载入演示问题」「开始引导」「继续提示」「我的思路」「获取反馈」「换一种解释」「L4 相似例题」等交互，右侧展示分类置信度与可手动调整的分类，下方是可展开的引用卡片。四种状态（初始 / 加载 / 回答 / 错误）都有明确反馈；层级阶梯直观展示当前所处位置与被钳制的原因。

> 配图：`docs/assets/teaching-l1.png`（L1 页面、引用卡片）。

### 5.3 截图报错分析（`app/errors/` + `ErrorView.vue`）

`ocr.py` 提供三种通道：`auto`（配了视觉模型就用，否则本地 rapidocr）、`vision`（OpenAI 兼容视觉模型，需 `VLM_*` 配置）、`rapidocr`（本地 ONNX 离线可用）；`/api/errors/capabilities` 如实返回当前可用通道。识别结果可编辑，改完重新走一次完整分析链路。`parser.py` 抽取异常类型、文件、行号、关键语句，`analyzer.py` 复用检索与教学引擎给出可能原因、排查步骤与引用。

> 配图：`docs/assets/errors-demo.png`（截图识别与分析结果）。

### 5.4 前端交互与状态

4 个页面：首页（连接状态、知识库概况、演示模式横幅）、分层教学、知识库、报错分析。API 层使用 axios 统一封装，`TeachingResponse` 等类型与后端 Pydantic 契约对应。Vite 开发服务器把 `/api` 代理到后端，无需额外跨域配置；生产构建 `npm run build` 含 `vue-tsc --noEmit` 类型检查。

## 7 总结与展望

### 7.1 技术创新点

1. **检索驱动的四级引导式生成**：把 RAG 命中集合同时用于引用绑定与分层策略决策，L1–L4 的内容形态由检索结果约束，而非单一 Prompt 自由生成；配合服务端跳级钳制与「先提交尝试再解锁」机制，形成可验证的教学闭环。
2. **输出侧答案泄露护栏**：对生成内容做代码块长度截断、完整函数体骨架化、索要完整实现的话术收敛，把「不代写作业」从产品口号落实为可测试的服务端约束。
3. **离线可复现的轻量 RAG**：自建链路 + 512 维哈希向量 + 0.75/0.25 混合打分 + Chroma 嵌入式持久化，无需 GPU、外网或独立向量服务；演示模式下检索真实、回答模板化并显著标注。
4. **可解释的诚实设计**：引用只能来自本次命中集合、无据拒答、OCR 不确定性标注、AI 生成示例标记、`llm_status` 状态回传，使每一条输出的来源都可核对。

### 7.2 应用创新点

1. **反「代写作业」的交互模式**：以「拒绝给答案、只给可溯源提示」为产品定位，回应高校实训中 AI 滥用导致的学习过程缺失。
2. **截图报错与教学链路复用**：OCR 结果可人工修正后重跑，识别不确定性显式标注，把多模态入口接入同一套检索与分层策略。
3. **教师可维护的课程资料闭环**：上传、失败可见、分块预览、去重、删除清向量、重建索引，让答疑口径始终锚定本课程资料。

### 7.3 社会价值

作品把 AI 用于「促进理解」而非「替代完成」，有助于降低实训课程的答疑重复劳动，同时保护学习过程；离线可跑、无 Key 可复现降低了院校部署门槛；对幻觉、引用、密钥、代码执行的处理体现负责任 AI 的实践。演示模式中「检索真实、生成标注」的做法，也为教学场景里如何如实说明 AI 能力边界提供了一个可复用的范例。

### 7.4 局限与后续规划

| 局限（当前实现） | 后续规划 |
|---|---|
| 哈希向量为词面相似度，无语义泛化能力 | 可选接入语义 Embedding，保留离线通道作降级 |
| 仅 4 份自制示例资料 / 15 片段 | 扩充真实课程语料，建立评测集 |
| `stream: False`，无 SSE 流式与独立聊天页 | 补流式渲染与 RAG 对话主界面 |
| 无 Agent / 工具调用 / Function Calling | 让引擎按问题类型自主选择检索、报错指纹、排查清单等工具并可视化轨迹 |
| 无评测指标看板 | 扩展 `check_demo.py` 为 Recall、引用覆盖率、泄露率等可量化指标 |
| 前端主 chunk 1.11 MB，未做代码分割 | `manualChunks` 拆包 |
| 无公网在线演示地址 | 部署在线 Demo，作为可选加分项 |

> 说明：以上规划项**均不在当前代码中**，仅作为展望；Qdrant、JWT、教师端、评测看板属于早期备选方案，与最终实现不一致，不作为本作品已交付功能。
